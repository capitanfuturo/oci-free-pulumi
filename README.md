# oci-free-pulumi

This is an example of how to use [pulumi](https://www.pulumi.com/) and the free tier of [OCI](https://www.oracle.com/it/cloud/) to create via infrastrucutre as code an instance with:

- 2 cpu
- 12 GB of RAM
- Ubuntu 22.04
- ARM powered instance VM.Standard.A1.Flex
- 100 GB disk space
- volume backup
- backup policy
- public ip

## Requirements

A linux or WSL2 enviroments with:

- Make command installed
- docker and docker-compose

A Pulumi account (I'm using a free one)

A OCI account (I'm using the free tier)

## Getting started

Clone the repository, rename `template.env` in `.env`. Change properly the env variables and use the command `make oci` to build the docker image and start the compose. You will notice that all your localhost configuration such as `~/.ssh` and `~/.oci` directories will mounted into the container context.

So you can store your env and secret locally without shared with the code.

### Where to find the `.env` values

- **USER_OCID** (`ocid1.user.oc1..aaaa...`) — OCI Console → profile icon (top right) → *My profile*, "OCID" field of the user.
- **FINGERPRINT** — same *My profile* page → tab *Tokens and Keys* → *API keys* section. If you don't have an API key yet, generate one there ("Add API Key"): OCI lets you download the private key (used for `PRIVATE_KEY_NAME`) and shows the fingerprint plus a ready-made config block (which also contains the user OCID, tenancy OCID, and region).
- **TENANCY_OCID** (`ocid1.tenancy.oc1..aaaa...`) — OCI Console → profile → *Tenancy* (your tenant name), or the "Tenancy: `<name>` (OCID: ...)" link at the bottom of every console page.
- **PRIVATE_KEY_NAME / PUBLIC_KEY_NAME** — the API key pair generated in the "Add API Key" step above. Save them under `~/.ssh` on the host (it's mounted into the container at `/root/.ssh`), and set only the file name here (e.g. `ssh-oci.key` / `ssh-oci.pub`), not the full path.
- **INSTANCE_PRIVATE_KEY_NAME / INSTANCE_PUBLIC_KEY_NAME** — a **separate** SSH key pair generated by you (e.g. `ssh-keygen -t ed25519 -f ~/.ssh/instance-key`), used to SSH into the created VM (injected as `ssh_authorized_keys`) and for the Ansible inventory.
- **REGION** — the OCI region of your account (e.g. `eu-milan-1`, `eu-frankfurt-1`), shown at the top right of the OCI console (region selector) or in the config block shown when you generate the API key.
- **PULUMI_ACCESS_TOKEN** — [app.pulumi.com](https://app.pulumi.com) → profile icon (buttom left) → *Access Tokens* → create a new personal token.
- **NOIP_HOSTNAMES / NOIP_USERNAME / NOIP_PASSWORD** — create an account on [noip.com](https://www.noip.com), register a free hostname, and use your login credentials there. Required both for the No-IP DDNS client and as the public domain for the Headscale VPN server (`https://<NOIP_HOSTNAMES>`).

Note: the OCI free tier limits you to 2 API keys per user at a time — if you already have others active, you may need to remove one before generating a new one.

## Creating the stack

Once you are inside the container shell (`make oci`), the Pulumi stack `oci-free` is already selected and configured, so you just need to run:

```
cd infrastructure
pulumi up
```

Review the proposed plan and confirm to provision the OCI infrastructure (compartment, VCN, instance, public IP, backup policy, etc.).

## Configuring the new instance

Once `pulumi up` succeeds, the instance still needs to be configured with Ansible — this handoff is manual, Pulumi does not update the inventory automatically.

1. **Find the instance's public IP:**

   ```
   pulumi stack output instancePublicIp
   ```

2. **Populate the Ansible inventory.** Copy `inventory.template.ini` to `inventory.ini` (first time only) and set the public IP:

   ```
   cd /code/oci-free/configuration
   cp inventory.template.ini inventory.ini
   ```
   ```ini
   [ociserver]
   <PUBLIC_IP>
   ```

3. **Run the playbook:**

   ```
   cd /code/oci-free/configuration
   bash ansible-init.sh
   ```

   This runs `ansible-playbook playbook.yml -i inventory.ini --private-key ${INSTANCE_PRIVATE_KEY_NAME}`, which in order: removes `snapd`/`unattended-upgrades`, updates the system, configures NTP and swap, and reboots (`ubuntu-bootstrap`); installs Docker and adds `ubuntu` to the `docker` group (`docker`); if `NOIP_*` variables are set in `.env`, installs and daemonizes the No-IP DDNS client (`noip`); and deploys the [Headscale](https://headscale.net) VPN server stack, using `NOIP_HOSTNAMES` as its public domain (`headscale`) — see [Headscale VPN server](#headscale-vpn-server) below.

   The instance must already be reachable via SSH using the `INSTANCE_PRIVATE_KEY_NAME` key (the one injected as `ssh_authorized_keys` during provisioning).

## Headscale VPN server

The `headscale` role deploys a self-hosted, Tailscale-compatible control server on the instance, as three Docker containers managed via `docker compose` in `/opt/headscale`:

- **headscale** — the control-plane server itself, storing state in a local SQLite database and using Tailscale's default DERP relay map.
- **headscale-admin** — a static web UI to manage users, nodes and ACLs, served under the `/admin` path.
- **caddy** — reverse proxy in front of both, terminating TLS with an automatic Let's Encrypt certificate for the domain in `NOIP_HOSTNAMES`.

No changes to the Pulumi infrastructure are needed: the default security list already opens ports 80/443, which is all Headscale requires (it doesn't act as a DERP relay, so no extra WireGuard port has to be exposed).

### First-time setup

After the playbook has run at least once, SSH into the instance and:

1. Create your first user:

   ```
   docker exec -it headscale headscale users create <username>
   ```

2. Generate an API key for the admin UI:

   ```
   docker exec -it headscale headscale apikeys create --expiration 90d
   ```

3. Open `https://<your-domain>/admin` and paste the API key into headscale-admin's Settings page.

4. Connect a client:

   ```
   tailscale up --login-server https://<your-domain>
   ```

   Approve the new node from the admin UI, or with `docker exec -it headscale headscale nodes list` / `headscale nodes register`.

## Destroying the stack

To tear down the provisioned infrastructure, from the same container shell run:

```
cd infrastructure
pulumi destroy
```

Review the destruction plan and confirm to remove all the resources created by the stack.

If you also want to remove the stack itself from Pulumi (not just its resources), you can additionally run:

```
pulumi stack rm oci-free
```

This is optional and irreversible, so only do it if you don't plan to recreate the stack under the same name.

### Troubleshooting: `pulumi destroy` fails to delete the compartment

If `pulumi destroy` fails with an error like:

```
oci:Identity:Compartment (oci-free-compartment):
    error: deleting ...: During deletion, Terraform expected the resource to reach state(s): DELETED, but the service reported unexpected state: ACTIVE.
```

it means OCI is refusing to delete the compartment because it still contains resources — even ones Pulumi doesn't manage directly, such as automatic boot volume backups created by the backup policy, or instances that were terminated outside of Pulumi and haven't been purged yet.

List everything still present in the compartment (requires the `oci` CLI, available inside the container):

```
oci search resource structured-search --query-text \
  "query all resources where compartmentId = '<COMPARTMENT_OCID>'"
```

For each leftover resource, delete it with the matching `oci` command, e.g. for a boot volume backup:

```
oci bv boot-volume-backup delete --boot-volume-backup-id <OCID> --force
```

Re-run the search until it returns no items, then run `pulumi destroy` again. If a `TERMINATED` instance still shows up and nothing else is left, OCI usually purges it automatically within a few hours/days — there's no command to force it.
